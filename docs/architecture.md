# 架构评估

> 承接 [decision.md](decision.md)：第一版 = Windows 桌面客户端 + 三栏工作区 + 一个「分层出题」Skill + CAS 验算 + Word 导出。

> 整理日期：2026-08-19

## 〇、真正约束架构的四条

放宽体积/性能/兼容性之后，剩下这四条。前三条四份笔记里有，**第四条全都漏了**。

| # | 约束 | 逼出的结果 |
|---|---|---|
| 1 | CAS 必须是 SymPy | 客户端里**必须有 Python 运行时**。决定了不可能是纯 JS 应用 |
| 2 | Word 公式必须可编辑（OMML） | 需要 pandoc 转换链，多一个二进制依赖 |
| 3 | 产物是文件，Agent 要读写并出 diff | 天然适配自带文件工具的 agent harness，不要自己造 |
| 4 | **API key 不能放在教师机器上** | 必须有一层中继服务。这推翻了"纯本地应用"的默认假设 |

注意这四条**都不是性能或体积问题**，是正确性和安全问题——放宽约束不影响它们。

## 一、选型总表

| 层 | 选择 |
|---|---|
| 外壳 | **Electron（最新版）** |
| UI | React + TypeScript + Vite；编辑器用 Monaco；公式预览用 KaTeX |
| Agent 循环 | **Claude Agent SDK（TS）**，跑在主进程 |
| 工具层 | **单个 Python MCP server（stdio）** |
| Python 运行时 | **官方 embeddable Python + 预装 wheel**，随包分发 |
| 数据 | **纯文件**。第一版不要数据库 |
| 导出 | **pandoc**（随包分发），Markdown + LaTeX → docx（OMML） |
| 作图 | matplotlib → SVG |
| 模型接入 | **薄中继服务 + 模型路由** |

一句话：**Electron 里跑 Claude Agent SDK，Agent 通过 MCP 调用一个常驻 Python 工具进程，产物是本地课时文件夹里的纯文件，模型走自建中继。**

## 二、外壳：Electron 最新版

已定，不再比较 Tauri。顺带说明它本来也是更优解：Claude Agent SDK 的 TS 版需要 Node 进程，Electron 主进程天然是 Node，直接跑；Tauri 要么额外起 Node sidecar，要么用 Rust 重写 loop。

进程划分：

- **主进程（Node）**：窗口、文件系统、Agent SDK 编排、MCP client、中继调用
- **渲染进程（React）**：三栏 UI
- **Python 子进程**：MCP server，常驻（sympy/matplotlib 的 import 开销一次性付掉）

**体积和性能放开后可以放心用的东西**：Monaco 编辑器、KaTeX、完整 matplotlib、随包分发 pandoc、随包分发完整 Python 发行版。都不用再纠结。

## 三、Agent 层：Claude Agent SDK

`@anthropic-ai/claude-agent-sdk` —— 注意它和 Anthropic API SDK 里的 `tool_runner` 是两个不同的东西，别混。

选它的核心理由：[grok.md](grok.md) 反复强调的那个循环 **「改文件 → 出 diff → 等老师采纳」，正好是 Agent SDK 的默认行为**。它自带 Read / Write / Edit / Glob / Grep、agent loop、上下文管理、权限确认、MCP client、子 agent。把工作目录指向课时文件夹，diff 和采纳几乎是白送的。自写 loop 要花几周重做同样的事，且做不到同样成熟。

三个 Skill（备课 / 出题 / 错因）落成 SDK 的 skill + 系统提示 + 工具契约组合，第一版只实现出题。

**权限设计**：Agent 写工作区文件不需要确认（有 diff 兜底），但**导出给学生的动作要卡一道**——红色状态的题禁止导出。这个检查放在工具层，不依赖模型自觉。

### 3.1 会不会被锁死在 Claude 模型上

**技术上不会，但官方不支持——这两件事要分开看。**

- **机制**：SDK 读 `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN`。耦合点是 **Anthropic Messages API 的报文格式，不是模型本身**。任何按这个格式提供 `/v1/messages` 的服务都能接上——LiteLLM 之类的网关正是靠这个转发到 300+ 模型。原生还支持 Bedrock / Vertex。
- **国产模型已经有现成的兼容端点**（为 Claude Code 生态做的）：Kimi `api.moonshot.cn/anthropic`、GLM `open.bigmodel.cn/api/anthropic`、MiniMax `api.minimaxi.com/anthropic`，DeepSeek、Qwen 也有对应方案。
- **但官方态度是明确的**：`claude-agent-sdk-python` issue #410 问的就是这件事，被 close 成 not planned。意思是 Anthropic 不会测、不会保证、坏了没有支持渠道——**我们自己承担**。

**关键：我们已经要建的中继服务（§8.3）就是这个开关。** 客户端的 `ANTHROPIC_BASE_URL` 指向自家中继，中继背后接什么模型是我们的事。为密钥安全建的那一层，顺带就是模型可替换性的接缝——不用为此额外设计。

这对国内落地是实打实的：Anthropic API 在大陆不能直连，学校也可能要求国产模型或私有化部署。中继同时解决出网和换模型两件事，[claude.md](claude.md) §9 那个"纯云端还是校内私有化"的问题，答案就落在这一层。

**真实代价不在配置，在调优。** 换模型是一行环境变量，但 harness 的系统提示、工具描述、agent loop 全是按 Claude 的行为写的。换成能力弱的模型，多步工具调用和文件编辑的成功率会明显下降，thinking、prompt caching 这些也会退化或失效。所以：**接缝留着，但第一版不要真的去接**——先用 Claude 把"生成的题到底对不对"这件事验证完，换模型是后面的工程题。

**商务条款要有人看一眼**（做的是给学校的商业产品，不是内部工具）：SDK 的使用受 Anthropic Commercial Terms 约束，即便用于对外产品；品牌上不能叫 "Claude Code"，可以叫 "XX Powered by Claude"；另外不允许第三方产品给终端用户提供 claude.ai 登录——我们本来就是 API key + 自家中继，天然合规。

## 四、工具层：一个常驻 Python MCP server

[claude.md](claude.md) §6 提议拆成题库 / 绘图 / 排版 / 学情四个 MCP server。方向对，但第一版不要拆——理由不是性能，是**复杂度**：四个进程意味着四份启动逻辑、四倍崩溃面。按域分组工具名，需要时再沿着命名切开。

```
verify_algebra      SymPy 求解 / 化简 / 验根 + 第二条独立路径复核
verify_answer_shape 系数反向控制：整数解、判别式完全平方、比例可约
save_problems       写 problems.json 的唯一入口：校验结构 + 强制重跑验算
render_figure       函数图象 / 数轴 / 统计图 / 几何图 → SVG（matplotlib，可校验）
render_illustration 应用题的生活场景插图 → PNG（网关的生图模型，**不可校验**，见 §4.20）
export_docx         Markdown + LaTeX → docx（pandoc，OMML 公式）
```

### 4.1 为什么 problems.json 不让 Agent 直接写

原设计是让 Agent 用内置 Write 写 problems.json，这样有 diff 可看。**实跑第一次就否掉了。**

两个问题，第二个是要命的：

1. **手写含 LaTeX 的 JSON 必然出错。** `$\Delta$` 在 JSON 里得写成 `\Delta`（双反斜杠），
   实测第一轮就写出了非法 JSON，顺带还把 `solution` 写成了字符串而不是数组。
2. **verify 字段不能由模型填。** 如果模型只是「把工具返回的结果抄进去」，
   它同样可以凭空编一个 `{"status": "green"}`。系统提示里写一百遍「不要编造」也
   只是道德约束——而这是产品唯一不能犯的错，不能只靠道德约束。

所以改成：模型提交**题目 + 该怎么验它**（`check` 字段），`save_problems` 自己跑验算、
自己写 `verify`，红的直接拒收不落盘。模型碰不到那个字段。

代价是 problems.json 没有 diff 了。可以接受：它是机器结构化存储，
教师真正要审的 diff 在 homework.md，而中栏的题目卡片（带绿/黄/红色带）比 JSON diff
更适合人来复核。散文类产物仍然走 Write/Edit。

为什么是 MCP 而不是自定义 IPC：Python 进程本来就要存在，MCP 是 Agent SDK 原生说的协议，省掉协议层；而且每个工具能脱离客户端单测——对"验算器必须很苛刻"这个目标很重要。

**验算是纯代码，不许有模型参与。** 双路径校验（求解一次 + 代回原式一次），两者一致才给绿。

---

### 4.2 给了硬约束就必须给满足它的手段

出题 Skill 的系统提示有一条硬要求：「不要凭记忆写课标条目号」。
但 Agent 的 cwd 是**课时目录**，里面只有 meta.json 和 problems.json，
教材数据在仓库的 curriculum/ 下——它够不着。

实测后果：老师选中课时、输入「生成三道题目」，Agent 读到 meta.json 里的
`tp-01-01`，不知道是什么，翻两轮文件找不到，然后收尾了事。**153 秒、零产出**，
界面上表现为「没反应」。我们导入的 255 个知识点它一个都看不见。

补了 `lookup_curriculum` 工具之后，同样的输入能正常出题。

**教训**：约束和手段必须成对出现。只写约束不给工具，模型要么违反约束（编造），
要么卡死（空转）——两种都比没有约束更糟。

### 4.3 done 不能只信 Agent 的说法

同一次排查里发现的另一件事：Agent 空转收尾时，`result.subtype` 仍然是
`success`，summary 还写着「按 A/B/C 出三道题并写入 problems.json」——
而一道题都没写。UI 照着 `ok=true` 显示了一个**绿色的成功框**。

这比没反应更糟：老师以为成了。

现在 `runAgent` 在收到 done 时会核对 problems.json 的题目数，
没变化就把 ok 改成 false 并说明情况。**产物类的完成信号必须对着文件核实，
不能只信模型的自述。**

### 4.4 画图题：图与题干必须同源，且这件事要能被机器验

初中数学的「画图题」是两回事，处理方式相反：

| | 题目**配图** | 要求学生**作图** |
|---|---|---|
| 例 | 「如图，△ABC 中 ∠C=90°…」 | 「画出 y=2x+1 的图象」「尺规作角平分线」 |
| 谁画 | 我们生成 | 学生自己画 |
| figureRefs | 有 | **没有**（给了等于把答案印在题面上） |
| type | 解答/填空 | `作图` |
| 验证 | 图要过坐标校验 | `manual` → 黄色，教师确认作法 |

配图那条的红线是 [grok.md](grok.md) §5 的「**图与题干条件必须同源生成**」。
最典型的翻车方式是题干写 ∠C=90°、画出来是钝角——学生拿尺子照着量，越量越错。

做法：`render_figure(kind="geometry")` 要求模型给出**坐标**，同时把题干里的每个
条件写成 `asserts`（length / angle / parallel / equal_length / collinear）。
本工具按坐标**实算**校验，对不上就拒绝出图并报出差多少。

坐标是模型给的，但「坐标是否满足题干条件」是算出来的，不归它说了算——
和 `save_problems` 不采信模型自填的 verify 是同一个原则。

`save_problems` 还会校验 `figureRefs` 指向的文件真实存在、且与题干里的
`![](...)` 引用一致。引用一张不存在的图，导出到 Word 里就是个空洞，
老师往往要到打印发给学生之后才发现。

### 4.5 工具太多会让模型「看不见」工具

实测过一个很难查的故障：Agent 回「当前会话里没有可用的 save_problems 工具」然后收尾。
而 init 消息里那 6 个 `mcp__mathtools__*` 明明都在。

原因是 **Claude Code 默认带 33 个内置工具**（Task / Cron / Worktree / Monitor /
Workflow / WebSearch…），加上我们的 6 个共 39 个。工具一多就触发 tool search 的
**延迟加载**——MCP 工具的定义不进提示词，模型得先搜索才看得见；它没搜就断言不存在。

两处修正：

1. MCP server 配 `alwaysLoad: true`，本 server 的工具始终进提示词，不被延迟。
2. Skill 加 `disallowedTools`，把备课用不到的内置工具全关掉，内置从 33 个降到 5 个
   （Read / Write / Edit / Glob / Grep）。关掉 Bash / PowerShell 顺带也是安全考虑：
   教师端产品不该能执行任意命令。

注意 **`allowedTools` 只管「免确认」，不缩小工具集**——想减少工具必须用
`disallowedTools`。这两个名字很容易让人以为是一对白/黑名单，其实不是。

### 4.6 homework.md 是派生视图，不是第二份内容

原设计让 Agent 用 Write 写 homework.md，理由是「那里 diff 对老师有价值」。**这个理由站不住。**

它和 problems.json 内容重复：老师删掉一道题、或者出了几道变式，problems.json 变了
而 homework.md 没变——**他手上那张要发给学生的卷子就是旧的，而且看不出来**。
这是所有 bug 里后果最实的一种：错的卷子会真的印出来发到学生手上。

[claude.md](claude.md) §4 早写了正解：「单一 source of truth，多种导出，改一处全联动」。

现在：problems.json 一变，主进程就重新生成 homework.md。老师要定制的固定抬头
（姓名/班级）放 `preamble.md`——**那是模板，不是内容**，重新生成不会丢。
文件头有生成标记；老师整个重写过（标记没了）就不再覆盖。

循环防护：重生成会写文件、触发下一次监听，但内容没变时返回 `changed=false`
且不写盘，所以一轮就收敛（实测触发 1 次）。

**「diff / 采纳」这个承诺就此转化了**：problems.json 走闸门写、不给 diff；
homework.md 是派生的、不需要 diff。真正的复核界面是中栏的题目卡片
（带绿黄红色带、可单独删除），比读 JSON diff 更适合人。

### 4.7 save_problems 需要 append

两个实测出来的后果，都不轻：

1. 「出变式」只能整卷重交——追加会被覆盖掉。
2. 一次提交 3 道题，**工具参数就会被截断**，模型只好重试，一轮跑了 585 秒。
   改成 2 道一批 append 之后同类任务 145 秒。

所以 `mode="append"` 是刚需而不是便利。id 撞车会被拦下并提示改用 replace。

### 4.8 统计图不能拿几何工具画

老师让出「统计图表」的题时，工具层只有函数图象和数轴，Agent 只好用 `kind="geometry"` 硬凑。
几何渲染器会给每个点标名字（△ABC 需要标 A、B、C），于是条形统计图上出现一堆
B2、B3、F2，没有坐标轴、没有类别名、没有数值——**学生根本读不了那种图**。

几何图和统计图的画法要求是相反的：几何要标点，统计要标类别和数值、藏掉点。
补了 `bar` / `line` / `pie` / `histogram` 四种，并在 Skill 提示里明写禁止用 geometry 凑。

统计图也有对应的「同源」校验：`assert_total` —— 题干说「全班共 40 人」就填 40，
各项之和对不上直接拒绝出图，免得画出一张和题干自相矛盾的图。

### 4.9 会话历史要落盘

原来每次运行都 `setEvents([])` 清空，关掉应用全丢。老师会想「上次那句话是怎么说的」
再复用，这也是 [claude.md](claude.md) §2 说的「教师档案靠动作自动积累」的原料。

现在每一轮存进课时目录的 `conversation.json`（只增不删，留最近 200 轮），
右栏常驻显示，点一条就能重发。每条带**产出增量**（+8 道），
一眼能看出哪次真的有东西落盘、哪次是空转。

### 4.10 图片输入走文件，不走内存

[claude.md](claude.md) §3 的 OCR、[grok.md](grok.md) §4 的错因诊断、§7 手势清单里的
「拍照作业」都指向同一个能力：老师能把拍的照片、教材截图、学生作业丢进来。

实现上有两条路，选了后者：

| | 塞进提示词的 content block | **存进课时目录，让 Agent 用 Read 看** |
|---|---|---|
| 图片归属 | 一次性，用完就没了 | **成为工作区的一部分** |
| 能否当题目配图 | 不能，要重新画一张 | 能，路径直接写进 figureRefs |
| 能否随卷子导出 | 不能 | 能 |
| 老师能否自己打开 | 不能 | 能，就在 assets/ 里 |

Claude Code 的内置 Read 工具本来就能看图，所以这条路不需要额外机制——
只要把图落进 `assets/upload-<时间戳>-<原名>.<ext>`，在提示词里给出路径即可。

这和「文件是唯一事实来源」是同一个原则：**凡是有价值的东西都应该落盘**，
而不是只活在某一轮对话的上下文里。

安全边界：只认图片 MIME、上限 20MB、文件名过 `safeSegment`、写入前校验路径没越出课时目录。
渲染层能直接调它，不能变成往用户磁盘写任意文件的通道。

### 4.11 老师改题必须重新验算

[claude.md](claude.md) §5：「**产物必须可编辑**。教师一定会改；改动本身就是最好的偏好信号。」

但编辑和「验证戳」是有冲突的：老师把答案从 2 改成 3，那个绿色的「已验证」
就变成了谎言，**而它还是可导出的**——等于产品在替一道错题背书。这比不让改更糟。

解法：**保存时走和 Agent 完全一样的闸门**，按 `check` 规格实跑验算再落盘。
验不过就不保存，原题原样留着——不能既没改成又把原题弄丢了。

前提是 `check` 得跟着题目落盘。原来它在 `save_problems` 里被 `k != "check"` 剥掉了，
于是改完根本没法重跑。现在保留，顺带也让「出变式」有了现成的结构模板。

`mode="replace_one"` 单列出来：老师改一道题不该动其余的，也不该改变它在卷子里的位置。

**验算规格开放给老师编辑**。他改了答案就得同时告诉机器「现在该验什么」。
这看起来技术，但它恰恰是最该让老师看见的东西——**凭什么说这道题是对的**。

### 4.12 图能放大

缩略图里看不清刻度和标注，而「看不清」正是老师判断一张图能不能用的关键。
题目插图和上传的附件都点得开：Esc 关闭、锁背景滚动、深色蒙层上给 SVG 垫白底
（那些图是黑线画的，不垫底就糊成一片）。

附件用本地 `objectURL` 做缩略图，发送后和卸载时都要 `revokeObjectURL`——
图已经落盘了，那几个引用只是预览用的内存。

### 4.13 会话状态必须按课时分开

原来 `events` 和 `busy` 是全局的一份。老师一边等生成、一边去看下一节课，
看到的是上一节的记录和「生成中」——**串台**。

根治办法不是在渲染层做过滤，而是**让 agent 事件带上 lessonId**：
主进程 `send(lessonId, event)`，渲染层存成 `Record<lessonId, AgentEvent[]>`，
`busy` 变成 `busyLesson: string | null`（主进程本来就只允许同时跑一个）。

于是「生成中」这个状态自然落在左栏对应的那一条课时上，切走了也还在那儿显示。

**dev fixture 也得按 id 返回不同的课时**——原来不管传什么 id 都返回同一个对象，
`current.meta.id` 永远不变，这类隔离 bug 在浏览器里根本验不出来（踩过一次）。

### 4.14 变式不该是盲盒按钮

[claude.md](claude.md) §4 把「变式生成器」列为最高价值的功能，但原来它是点一下就
直接发一句写死的提示词：不确认、不能补充要求，老师点完只看到右栏开始滚事件，
既不知道会出几道也不知道变哪里。

改成先弹对话框：出几道、变什么方向（换数字 / 换问法 / 逆向命题 / 一题多解 /
踩常见错因，来自同一节）、目标分层、额外要求。原题的 `variantSeed.constraints`
会自动带上。确认后才发。

### 4.15 「慢」不是一个可排查的描述

老师说「感觉生成有点慢」，第一反应总是「换个模型试试」。这个反应恰好是对的，
但**理由和大多数人以为的不一样**——所以还是得先量，不能靠猜。

把一轮生成拆开，耗时是三项相乘相加：

    总时长 ≈ 每次请求的固定开销 × 来回轮数 + 真正的生成时间

三项的责任人不同：固定开销归网关，轮数归提示词和工具设计，生成时间归模型。

**实测（2026-08-21，网关 kittycat:12580，同一句话「出 3 道 A 层基础题」）：**

| | `mathcopilot`（无会话包） | `mathcopilot` | `auto/claude-sonnet` |
| --- | --- | --- | --- |
| 端到端 | 454 s | 331 s | **194 s** |
| 来回轮数 | 12 | 8 | 13 |
| 平均每轮 | 38 s | 41 s | **15 s** |
| 累计入 token | 160,817 | 81,904 | **18,137** |
| 命中提示词缓存 | 0 | 0 | **94,336** |
| 并行调工具 | 否 | 否 | **是**（3 次验算同一轮发出） |
| **产出题目** | **0** | **0** | **3（全绿，双路径）** |

三件事一次性看清楚了：

1. **别名之间的差距是数量级的，而且首先差在能不能用上。** `mathcopilot` 两轮都
   跑出 0 道题，失败形状一模一样：验算调满，从不调 `save_problems`。这不是慢，
   是白跑。`auto/claude-sonnet` 194 秒出 3 道全绿的题。
2. **提示词缓存是通的——但只对部分别名生效。** 一度以为「中转网关不透传
   `cache_control`」，是错的：sonnet 这轮命中 94,336 token，入 token 因此只有
   `mathcopilot` 的 1/4。**是 `mathcopilot` 这条路由拿不到缓存**，于是每轮全额重算。
3. **会话包确实有效。** 补上后轮数 12→8、入 token 直接砍半。但它救不了一个
   撑不住工具流程的模型——补了照样 0 产出。

网关自身的固定开销是真的，但**是次要项，且抖动很大**（1.2–10.6 s，一个 118 字节的
400 响应也要 1.2–3 s）。它在 sonnet 那轮占 27%，在 mathcopilot 那轮占 7%——
比例高低取决于分母，别被百分比误导。

还剩的可优化项，属于我们自己的账：

- **13 轮偏多。** sonnet 已经会并行发工具调用（三次 `verify_algebra` 同一时刻发出），
  所以「把验算工具改成批量收题」的收益比预想的小——真正的重复在于
  `save_problems` 本来就会按 check 规格重跑验算（§4.1），Agent 事先那几次
  `verify_algebra` 是白验的。该改的是提示词，不是工具签名。
- **首个动作要等 74 秒。** 这段时间界面上只有「正在处理…」，老师完全不知道发生了什么。

为此加了两样：

- `RunStats` 挂在 `done` 事件上（`ms` / `apiMs` / `turns` / token / 缓存命中），
  界面落成结果框底部一行小字。**轮数和缓存命中必须可见**，否则没人会想到去查。
- `pnpm check:speed [别名]`（[check-speed.ts](../apps/desktop/scripts/check-speed.ts)）：
  先量网关固定开销，再跑一轮真实生成，算出占比，并**核对到底产出了几道题**。
  带别名参数是关键——「是不是模型的问题」只有同路径换模型对比才能答。

写脚本时踩的两个坑，都值得记：

- 第一版**漏了会话包**，Agent 只好自己去 `lookup_curriculum` 找上下文，轮数被凭空
  推高。测性能的脚本必须和主进程走**完全相同**的那条路，否则量出来的是脚本的毛病。
- 第一版**不核对产出**。于是 454 秒 0 道题被读成了「有点慢」——而它其实是彻底失败。
  **任何性能测试都必须同时断言功能成立**，否则最慢的那次很可能根本没干活。

### 4.16 闸门会悄悄塑造产物：选择题的例子

老师反馈「生成的题型不丰富」。实测 14 个课时 72 道题：

| 题型 | 数量 | 占比 |
| --- | --- | --- |
| 解答 | 50 | **69.4%** |
| 填空 | 13 | 18.1% |
| 选择 | 8 | 11.1% |
| 作图 | 1 | 1.4% |
| 证明 | **0** | **0%** |

初中几何证明是中考大题主力，一道都没出过。原因有三层，**第三层才是根因**。

**一、提示词里没有「题型」这一节。** 十个小节有「分层」没有「题型」，
五种合法值（选择/填空/解答/证明/作图）从没列出来过，`type` 唯一被解释的地方
是画图题那节里的一句「填 `"作图"`」。模型只能猜，于是默认全填 解答。

**二、数据模型没有 `options` 字段。** 选项被塞进题干字符串
（`"A. 1　　B. 2　　C. 3　　D. 4"`）。后果不只是排版难看：没法逐项验证、
没法只换干扰项出变式、**没法校验「有且仅有一个正确选项」**。

**三、验算体系没有选择题这一档 ← 根因。** `check` 只有
solve/identity/evaluate/manual 四种，而选择题的答案是「B」一个字母，
四种都表达不了「B 对应的值是 2，而 A/C/D 都不是 2」。于是选择题只能标
manual → 黄色（8 道里 7 道），而提示词又明写着「不要为了让题目通过而标成
manual——那是把能验的题主动降级」。

**模型于是理性地回避了选择题。** 这是本项目第二次遇到同一类问题（第一次是 §4.2：
「不许猜课标」却没给查课标的工具）：**闸门不是中立的，它会塑造产物。**
一个只能给某类产物发黄牌的验算体系，等于在悄悄劝模型别做那类产物——
而且从提示词上完全看不出来。

#### 加的这一档

`check.kind = "choice"`，选项放在题目的 `options` 字段（不在 check 里重复存——
两份就会不同步，不同步的那一刻验的就不是这道题了）。`basis` 说明正确答案怎么算出来：
给代数依据能到绿，给 manual 只能到黄。

跑三条路径，**第三条是加这一档最主要的理由**：

1. `option-set` —— 选项两两互异、正确项存在
2. `correct-option` —— 正确选项确实成立
3. `distractors` —— **其余选项确实都不成立**

「两个选项都对」是选择题最典型的硬伤，而它在题面上完全看不出来：老师印了发下去、
学生按另一个正确选项答被判错，才会发现。字符串比较查不出
`$x=2$ 或 $x=3$` 和 `$x=3$ 或 $x=2$` 是同一个答案，`1/2` 和 `0.5` 是同一个值，
`(x-1)(x-2)` 和 `(x-2)(x-1)` 是同一个式子——**实算才行**。

#### 两个必须分开的东西

**「判不了」不等于「验出来是错的」。** 这是实现里最容易搞错的一处：

- 正确选项是「以上都不对」→ 机器判不了 → **黄**，老师自己确认。
  判成红等于把一整类正当的选择题拦死在门外。
- 声称 B 对但实算 B 错 → 真矛盾 → **红**，禁止导出。

还踩到一个更隐蔽的：sympy 的 `parse_expr` 会把不认识的标识符**当成符号**接受，
于是「以上都不对」解析"成功"、比对失败、被当成一个**已验证过的**错误干扰项——
实际上根本没验。看起来更强的检查，其实是虚报。所以显式判掉散文选项
（去掉「或/和/、」这类连接词后还剩中文就算散文，免得 `$x=2$ 或 $x=3$` 被误判）。

#### 「下列…中，正确的是」这一族

这一族里**选项本身是待判的式子**，不是候选答案。basis 里用 `{option}` 占位，
工具把每个选项代进去逐个跑：

```
"basis": {"kind": "solve", "equation": "{option}", "variable": "x",
          "claimed_roots": ["2"]}
```

不加这个模式，这一整族只能落黄——实测老数据 8 道选择题里就有 1 道是这个形状。

#### 既有数据怎么迁

闸门现在硬要求 `type="选择"` 必须用 `choice`，所以老选择题（选项在题干里）
一编辑就会被拦下。**光报错不够**：老师改一个字被要求重建整个验算规格，多半就不改了。
所以编辑器一打开就把 check 落在 `choice` 形态上，并给一个「从题干提取选项」按钮。
拿工作区里 8 道真实老题验过，**8/8 能完整提取出 A–D**。

### 4.17 密钥要有地方填，也要有地方看见它从哪来

打包成客户端之后 `.env` 就不存在了，老师也不会去改环境变量——**必须有个界面能填**
网关地址、API Key、模型、图模型。

四个决定值得记下来：

**设置存 `userData/settings.json`，不存工作区。** 工作区是老师的*内容*：他会整个拷给
同事、放网盘、拖 U 盘。密钥混在里面等于跟着课件到处跑。

**逐项显示来源。** 优先级是 `设置界面 > .env > 进程环境 > 默认值`——设置界面排第一
是因为它是老师最近一次的**显式**动作。但这个顺序本身反直觉，看不见的时候会重演
config.ts 里记过的那个困惑：「我明明改了怎么没生效」。所以每一项旁边标出它实际来自
哪里，把优先级从「需要记住的知识」变成「屏幕上的事实」。

回落是**逐项**的，不是整份的。只填了地址、密钥留空时，密钥各自回落到 .env——
整份回落会造出最难查的状态：地址是新的、密钥还是旧的。

**能真打一次。** 地址末尾多带一个 `/v1`（SDK 会拼成 `/v1/v1/messages`）、别名在网关上
不存在、密钥过期——这三种都只在真正出题时才暴露，那时候老师已经等了几分钟，
而且报出来的错完全指不到设置页。「测试连接」发一次最小请求，并把 HTTP 状态翻成
能照着改的话（401 → 检查密钥，404 → 地址或模型名不对，且提示别带 /v1）。

顺带把往返耗时报出来。这个网关实测有 1.2–10.6 秒的每请求固定开销（§4.15），
测出 8 秒老师就知道后面出一组题会慢，而不是以为软件卡死。

**图模型让他点，不让他背。** 图模型名长这样：`codex/gpt-5.6-luna`，没人猜得到，
而且和文本模型**不是一套名字**——把 `MTC_MODEL` 那个别名填进去只会 400。
填错的唯一症状是四十秒后一个错误，那时候老师正等着插图出来。
所以旁边有个「看看有哪些」：`GET /v1/images/generations` 列出网关上的图模型
（这个查询免费，不出图），点一个填进框里。同一个路径 POST 才是出图。

留空是常态——大多数课用不到插图，所以它有默认值，并且**把默认值显示出来**：
空框会让老师没法判断插图到底是用什么画的。

**没配好时**：启动自动弹设置窗（只弹一次），顶栏挂一条不可关闭的提示，
`runAgent` 直接拒绝并说明去哪儿设置——不让 SDK 去撞认证错，那个错老师看不懂。

密钥仍然是明文存在教师机器上的。目标形态是第 8.3 节的中继（客户端只拿短期凭据），
这个界面是过渡形态，它至少让「密钥在哪、是谁填的、能不能换」变成显式可见的。

### 4.18 无边框窗口：省下的不是像素，是那条不属于这个产品的横条

原生标题栏那条灰蓝色的横条和三栏工作台完全不搭，而且白白占掉 30 多像素——
这个界面的纵向空间是稀缺的（左栏课时列表、中栏题目卡片都想要更多行）。
改成 `frame: false`，标题栏自己画：左边品牌记号 + 面包屑，右边设置 + 窗口控件。

几件不能省的：

**窗口控件必须自己接 IPC。** 渲染层拿不到 BrowserWindow，`window.close()`
在 Electron 里也不等于关窗口。三个动作各走一条 IPC。

**最大化状态必须由主进程推，不能查。** 双击标题栏、Win+↑、拖到屏幕顶端都会改变
状态，这几条路径渲染层一条都感知不到。不推的话，那个「最大化/还原」图标会和
实际状态对不上——一个一眼就能看出来、但很难想到原因的 bug。

**按钮尺寸照抄 Windows 的 46px、贴右边缘不留内边距。** 这不是抄外观，是抄
「屏幕右上角那一格」：鼠标甩到角上就能点中关闭，是 Windows 用户的肌肉记忆。
留了内边距，最大化时那一格就点不中了。关闭键悬停变 `#e81123` 同理——
那个红在 Windows 上本身就等于「关闭」。

**`thickFrame` 不能关。** 无边框窗口在 Windows 上靠 `WS_THICKFRAME` 支持拖边缘
缩放，关掉之后窗口就调不了大小。这条查过样式位确认：`style & 0x00040000 == true`。

**代价：Windows 11 的 Snap Layouts 悬停浮层没了。** 那个浮层只对**原生**标题栏按钮
弹出，自绘的接不到。Win+方向键和拖到屏幕边缘吸附都还在，只是少了悬停那一下。

### 4.19 图标：根号本身就是对勾

产品的核心不是「能出题」，是**每道题都验算过**（§4.1 的三态验证）。
而根号 √ 恰好既是数学符号、又长得就是一个对勾——符号和语义是同一个东西，
不用再往上叠「AI」或者「书本」的比喻。

**三态验证的绿色试着加进去，三版全部放弃：**

1. 大绿圆压在横线端点上 —— 根号被读成「一根线拴着个球」。
2. 缩小挪到横线上方 —— 变成了**通知角标**。角标在桌面应用上有确定含义
   （有未读、有状态），用在这儿是主动误导。
3. 横线末端染绿 —— 硬色界让横线看起来像两段拼起来的。

根号已经同时说清了「数学」和「验证」，再加绿色是在重复解释一件已经说清的事。

**小尺寸单独调笔画。** 16px 下按比例缩的笔画只剩一根发丝，整个符号糊成一团蓝。
所以 16/24/32 各有自己的加粗系数（1.45 / 1.3 / 1.2），不是缩出来的。
这也是没画 SVG 而用 Pillow 直接画的原因——从一份 SVG 缩下来做不到这件事。

预览拼版刻意做成**浅底一排、深底一排**：任务栏和标题栏两种底色都会遇到，
只在白底上看会漏掉深色下的问题。

### 4.20 情境插图：能生图，但**不能拿它画题干**

网关上有 5 个 `type=image` 的模型（`GET /v1/images/generations` 会列出来）。
第一反应是给 `render_figure` 加一个 `kind="scene"`——**否掉了，做成独立工具**。

理由是 §4.4 那条红线的性质：图与题干同源之所以成立，是因为它**能被机器验**——
模型给坐标，代码按 asserts 实算。生图模型给不出坐标，那套校验没有输入，
红线在它身上不是「弱一点」，是**完全失效**。

实测的证据很直白：让它画「两名学生测量旗杆高度」，出来的图旗杆底座是悬空的、
皮尺右端没对准杆底。当课本情境插图完全够用，当几何配图就是把错图发给学生。

所以边界**写在工具名上，而不是一个参数上**：

| | `render_figure` | `render_illustration` |
|---|---|---|
| 画的是 | 题干的一部分 | 帮助理解题意的场景 |
| 输入 | 坐标 / 表达式 / 数值 | 一句话描述 |
| 学生会去量它吗 | **会** | 不会 |
| 画错了能否发现 | 能（asserts 实算） | **不能** |
| 产物 | SVG | PNG |
| 耗时 | 毫秒级 | **30~40 秒** |

选错工具比选错一个 kind 参数更容易在日志里被看见，这是拆开的主要收益。

**光有工具名不够，得挡得住。** 按 §4.2「约束和手段必须成对出现」，
`illustration.py` 里有一张关键词表：描述里出现角度、三角形、坐标系、数轴、
统计图、圆这类词就在**发请求之前**拒绝，并直接告诉它该改用哪个 `kind`。
只写文档不挡，模型要么绕过去、要么卡住——两种都比没有约束更糟。

判断标准只有一条，写进 Skill 提示词里也是这一条：
**这张图里有没有学生会拿尺子去量、去读数的东西。**

三个实现取舍：

- **只用 stdlib 的 urllib**，不引 httpx/requests。tools-py 要随包分发，
  多一个依赖就多一份 `prepare_vendor` 的活，而这里只是一个 POST。
  随包的 embeddable Python 带 `_ssl.pyd` 和 libssl，HTTPS 直连没问题（已验）。
- **校验是 PNG 再落盘。** 把一个 JSON 错误串写成 `.png`、题干却照样引用它，
  表现是渲染层图裂、导出到 Word 是个空洞——和引用不存在的图一样难查。
- **凭据用 `MTC_IMAGE_*` 显式转发，不透传 `ANTHROPIC_*`。** 工具进程调的是
  网关的 OpenAI 兼容图接口，不是 `/v1/messages`；名字对上而协议对不上，
  下次排查会白走一圈。值来自设置界面解析出的生效配置，所以老师换了网关，
  出图跟着换，不会出现「问答走新网关、出图还打旧的」。

实测：`codex/gpt-5.6-luna`，1024x1024，**29.6 秒**，130 KB PNG，
用随包的 vendor python 直接跑通。`antigravity/gemini-3.1-flash-image` 当时在限流。

**对照实验（2026-08-25）：能不能干脆只留生图模型？** 四道题各画一张，逐张核对：

| 题目 | 结果 |
|---|---|
| Rt△ABC，∠C=90°，AC=3，BC=4，D 为 AB 中点 | ✅ 比例、直角、中点全对，排版比 matplotlib 还漂亮 |
| 条形图：一班 12、二班 8、三班 15、四班 5 | ✅ 柱高与刻度一致，中文类别名也写对了 |
| AB∥CD，AC 与 BD 交于 O，OA=3、OC=9 | ❌ **画成了对称的 X 形，OA:OC 成了 1:1**（题干是 1:3） |
| 抛物线 $y=x^2-2x-3$，标出 (−1,0)、(3,0)、(1,−4) | ❌ 标着 (−1,0) 的点画在 −1.5 上，顶点画在 0.5 上，**x 轴刻度从 2 直接跳到 4** |

两对两错。**关键不是错误率，是那两张错图和那两张对图一样可信**——
一样的印刷级线描、一样齐整的字母标注，没有任何东西提示你哪张该复核。
而 `render_figure` 那条路上，同样的错（坐标给成 78.69° 却声称 90°）会被当场拒绝，
连文件都不落盘。

所以答案是**两个都要留**，分工不变：

- 生图模型不能替代 `render_figure`——它对的时候你不知道它对，错的时候你也不知道。
- `render_figure` 也不能替代它——它画不了「妈妈在超市挑牛奶」。

顺带两条量的差距：0.03 秒 vs 30–49 秒，SVG（矢量，导出 Word 清晰）vs PNG。

**图里不要有文字**这条也写进了提示词，但理由要说准：不是它写不出中文
（上面那张条形图的「一班/二班/人数」全对），而是**写对写错你无从判断**。
抛物线那张的坐标标注就是错的，看上去却一样权威。要标注就写在题干里。

图模型别名走 §4.17 那套设置：界面上一项、能列出网关上有哪些、留空有默认值，
优先级和其余三项一致（设置 > `.env` > 环境 > 默认）。

**默认值有两份**：`illustration.py` 里一份、`settings.ts` 里一份。看着像重复，
但两边都需要——Python 那份服务「脱离客户端直接跑工具」（测试、cli），
TS 那份服务界面，而界面必须**显示**出实际会用哪个。不一致时以 TS 那份为准，
因为它会显式转发过去覆盖掉 Python 的兜底。

### 4.21 一整套题一张图都没有：闸门第二次塑造了产物

清点真实工作区（2026-08-25，13 个课时 81 道题）：

```
带 figureRefs 的题        15 / 81
题干写了「如图」的题        7 / 81
题干写了「如图」却没有图     0 / 81   ← 闸门本身是有效的
孤儿图（生成了没人引用）      4 张
```

最后两行放在一起就是结论。`save_problems` 那道闸门要求「题干写了『如图』就必须
真有那张图」，**它一次都没被违反**。模型没有绕过闸门，它绕过了**触发条件**：
不写「如图」，就不用出图，闸门也就管不着。81 道题里只有 7 道写了「如图」。

这是 §4.16（选择题那次）的同一个机制第二次发作：**闸门不会只挡住坏产出，
它会重塑产出去避开自己。** 上次是选择题被写成解答题，这次是配图题被写成纯文字题。

三条具体成因，按影响排序：

**一、提示词只在「如图」时要求出图，而出图那条路写满了失败模式。**
Skill 里配图那一节的篇幅几乎全在讲 asserts 会怎么拒绝、红线是什么、
「不要靠删 asserts 蒙混过关」；不配图那条路一句风险都没有。
从模型的角度看这是明确的成本信号：写「如图」= 多几轮工具调用 + 可能被拒 + 被指控作弊，
不写 = 零成本且没人管。于是「在 △ABC 中，DE∥BC 交 AB、AC 于 D、E」
这种教材上必然配图的题，被写成了纯文字。

代价不只是不好看。实测那道「直线 AB∥CD，AC 与 BD 相交于点 O」——
没有图的时候，X 型和 A 型两种构型都符合文字描述，**题目本身是有歧义的**，
图在这里是消歧的唯一手段。

**二、写法错了，工具指错方向。** `asserts` 的键是 `type`/`of`/`at`/`rays`/`equals`，
而 MCP 那层的参数叫 `geo_points`，命名本身就在诱导人写成 `points`/`kind`/`value`
（本仓库作者第一次调用就写错了）。写错时旧版返回的是：

```
第 1 条条件：未知的条件类型 None
hint: 调整 points 的坐标让它满足题干条件。不要删掉 asserts 蒙混过关……
```

**这是把它往死路上推**：真正要改的是键名，工具却让它去调坐标，
调多少次都修不好，还顺带指控它想作弊。合理的下一步就只剩放弃配图。
已修：写法错和条件不成立分开报，写法错时直接列出正确形状并注明「坐标不用动」。

同类问题还有一个：`labels`/`right_angles` 形状写错是**静默丢弃**的——
图照样出，只是少了直角符号和「AC=3」。模型以为标了，老师以为它没标。
已修：返回 `ignored` 列出被忽略的项。`server.py` 的工具文档里也补上了这四个
可选参数的形状——之前只写了「labels（边上的标注）」，形状全靠猜。

**三、上一轮生成的图，下一轮不知道它存在。** `buildPrompt` 给的是课时元信息 +
知识点 + 老师说的话，**从不提 `assets/` 里有什么**。「正数和负数」那节课的
`temp_number_line.svg` 就是这么变成孤儿的：第一轮生成了数轴、那一轮中断，
第二轮「继续生成」写了 8 道题，没有一道引用它。

### 三条都改了，效果验过

成因一改成**默认出图**：几何 / 图形认识 / 统计 / 概率的题默认配图，
判据是「这道题的条件里有没有位置关系」——「DE∥BC 交 AB 于 D」有，
「三边 7、24、25 判断是不是直角三角形」没有。这类知识点里有题没配图的，
**收尾时要逐条说明为什么**。那一节也重写了：原来通篇在讲会被怎么拒绝，
现在先讲什么时候必须有图，再把两种拒绝的修法分开写清楚
（写法错 → 改键名，坐标不用动；条件不成立 → 调坐标）。

成因三：`buildPrompt` 加了 `<课时里已有的图>`，逐条标出有没有题在引用它，
并说明「没人引用的要么用起来、要么当它不存在，但不要重画一张一样的」。

**验证（同一个知识点 rj-tp-31-02，真跑一轮 4 道题，281 秒）：**

| | 改之前的那节课 | 改之后 |
|---|---|---|
| 带图的题 | 0 / 8 | **4 / 4** |
| 孤儿图 | 有 | **0** |

预置的那张孤儿图被第一道题用上了，而且题干写的是「点 D、E 分别在边 AC、BC 上，
且 DE∥AB」——**和图里的实际坐标一致**，说明它读了图再写的题干，不是硬套。
之前那道有歧义的「AB∥CD，AC 与 BD 交于 O」这次也配了图，歧义随之消失。

## 四点五、打包

**Windows NSIS 安装包，`pnpm dist`。** 三件事值得记：

**asar 关掉。** 不是体积考虑，是可排查性。Agent SDK 带一个 315 MB 的 `claude.exe`，
塞进 asar 就没法直接执行，要靠 `asarUnpack` 加 Electron 的路径改写；那条链路出问题时
报的是 `spawn ENOENT`，完全指不到真正的原因。关掉之后装完就是一个普通目录，
坏了能 cd 进去自己跑一遍——和 vendor 用 embeddable Python 而不是 PyInstaller 是同一个理由。

**embeddable Python 的 `._pth` 会关掉「脚本目录自动进 sys.path」。**
这一条踩到了：`python.exe tools-py/server.py` 在开发期正常，打包形态下
`ModuleNotFoundError: No module named 'mathtools'`。修法是让 `server.py` / `cli.py`
自己 `sys.path.insert(0, 脚本所在目录)`，不指望解释器帮忙。

**准备脚本的验证必须照真实调用方式来。** `prepare_vendor.py` 第一版验证时手动
`sys.path.insert` 了一下，于是"验证通过"而真跑起来失败——正是上面那个坑。
**验证一旦和真实调用方式不同，它就只是在自我安慰。**改成直接
`python.exe <绝对路径>/server.py` 之后立刻暴露了问题。

装到用户目录、不要求管理员权限：学校机器上老师多半没有管理员账号。

## 五、Python 怎么装进客户端

**官方 embeddable Python + 预装 wheel（sympy、matplotlib、mcp），整个目录随包分发。**

不用 PyInstaller：不是体积考虑，是它在 Windows 上常被杀软误报，而且打包产物不透明、出问题难排查。embeddable 方案就是一个普通目录，坏了能直接进去看。Pyodide 方案随体积约束一起作废，不再考虑。

pandoc 同理，二进制直接随包走。

## 七、导出：唯一需要提前验证的技术点

- **pandoc**：Markdown + LaTeX 数学 → docx，数学自动转 OMML。单二进制，随包分发。

这一层是最容易在演示时翻车的地方——**公式如果变成图片，教研组改不了，产品当场失去意义**。所以它是唯一必须先动手验证的东西，见 §10。

## 八、模型层：路由与那个被漏掉的中继

### 8.1 模型路由

| 用途 | 模型 |
|---|---|
| 命题 / 变式生成 | `claude-opus-5` |
| 打标签 / 难度标注 / 去重判断 | `claude-haiku-4-5` |

命题用最强模型，正确性是产品命根子。[zcode.md](zcode.md) §5 说的"便宜模型打标、强模型命题"是对的。

### 8.2 成本与缓存

粗算一轮 8 道题的出题任务：输入 ~10k、输出 ~3k，单轮约 **$0.09**；算上验算失败重生成 1–2 次，实际 **$0.12–0.18/轮**。一位老师一天 3–5 轮 × 22 天 ≈ **$8–20/月/教师**。

**输出 token 是大头，不是输入。** 想省钱要压的是"一次生成多少题"，不是"塞多少上下文"。

prompt caching（把课标 + 教材小节 + 题型规范做成稳定前缀）能把输入成本压到十分之一，但那是优化，不是第一版的事——先把闭环跑通。

### 8.3 中继服务（四份笔记都漏了）

**API key 绝不能放在教师机器上**——Electron 应用的本地文件是可以被翻出来的。这是安全问题，不随性能约束放宽而消失。需要一层薄中继：

- 鉴权（教师账号 → 短期 token）
- 计量与配额（按 §8.2 的数字，这必须在架构里，事后加会很痛）
- 模型路由与降级

这不推翻"本地优先"：**学生数据仍然不出本机**，发给模型的只有题目、知识点、脱敏后的错误分布，不发学生姓名。这条要写进产品说明，是学校采购时会问的问题。

## 十、spike 结果（已跑通）

原先的 5 个 spike 里，机器兼容性、打包体积、Pyodide 备选都随约束放宽作废了，只剩一条端到端的线：

> Agent 生成一道二次方程题 → 经 MCP 调 SymPy 验算 → 导出 docx → 在 Word 里公式可编辑

**2026-08-19 跑通。** 逐项结果：

| 验证项 | 结果 |
|---|---|
| Agent SDK 在 Node 进程跑通 | ✅ |
| MCP 连上常驻 Python 工具进程 | ✅ `mathtools=connected` |
| Agent 走闸门写题（不绕过验算） | ✅ 调 `save_problems`，验算在工具内强制执行 |
| 双路径验算戳落进 problems.json | ✅ `sympy.solve` + `substitute-back` |
| pandoc 导出为 OMML 而非图片 | ✅ 6 个 `<m:oMath>`，2 个分式、1 个根式，0 图片，无 LaTeX 泄漏 |

OMML 那条原本以为「机器验不了、只能人去 Word 里点」，实际可以：解开 docx 检查
`word/document.xml` 里有没有 `<m:oMath>` 结构、有没有 `word/media/` 图片即可。
已固化成回归测试 `tools-py/tests/test_omml.py`，不再依赖人工。

**人工那一步仍然要做一次**，但只用来确认渲染效果好不好看，不再用来确认「是不是图片」。

### spike 顺带否掉的一个设计

原计划让 Agent 用 Write 直接写 problems.json，第一轮就写出了非法 JSON。
改成 `save_problems` 闸门，见 §4.1——这是整个 spike 最有价值的产出。
