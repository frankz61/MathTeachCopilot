# MathTeachCopilot 设计笔记

面向初中数学教师「备课 + 日常使用」的 agent harness 客户端。
本文是产品与架构层面的思考记录，不是最终方案，用于开工前对齐方向。

---

## 0. 一句话定位

不是「能写教案的聊天框」，而是一个**带教材上下文、带数学正确性保障、带可复用流程**的教师工作台。

---

## 1. harness 与普通 chatbot 的区别

教师不缺对话框。harness 的价值集中在三件事：

1. **常驻上下文**——教材版本与章节树、本学期进度、班级学情、教师个人风格。每次不用重新交代。
2. **确定性工具**——数学正确性、作图、排版必须由代码保证，不能交给模型自由发挥。
3. **可复用技能（skill）**——把「变式生成」「分层作业」「错题诊断」固化成流程，而不是每次靠提示词碰运气。

三者缺一，产品就退化成一个包装过的 ChatGPT。

---

## 2. 上下文层：真正的护城河

以**教材知识点树为主索引**，一切产物挂在树的节点上。

```
教材版本(人教/北师/苏科/华师)
└── 册(七上/七下/...)
    └── 章(如：一元二次方程)
        └── 课时(如：配方法解一元二次方程)
            ├── 课标条目映射
            ├── 教案 / 课件 / 学案 / 作业
            ├── 关联题目(题库引用)
            ├── 历年中考考法
            └── 教学反思(逐届累积)
```

在此之上叠三层档案：

| 档案 | 内容 | 作用 |
|---|---|---|
| 班级档案 | 分层情况、当前进度、高频错点 | 让「分层作业」「针对性练习」真的有依据 |
| 教师档案 | 导入方式偏好、板书习惯、语言风格、常用模板 | 生成的东西像他自己写的，而不是像 AI 写的 |
| 校本资源 | 本校往年试卷、集备记录、区中考真题 | 本地化，教研组能共用 |

> 教师档案是靠「教师改稿的动作」自动积累的，不是靠问卷填出来的。见 §5 人在环。

---

## 3. 工具层：必须是代码，不是模型

| 能力 | 实现要点 |
|---|---|
| **CAS 校验** | SymPy 求解 / 化简 / 验根。模型出的每道题都要过一遍机器求解，答案对不上就重生成 |
| **参数控制** | 出题时反向控制系数，保证答案「好看」（整数解、判别式为完全平方、比例化简干净）。这是教师判断题目是否专业的第一眼 |
| **作图** | 函数图像、几何图（JSXGraph / TikZ）、统计图；输出 SVG，可直接嵌 Word |
| **排版导出** | Word 中公式必须是**可编辑的 OMML**，不能是图片——教研组一定要改。另需 A4 双栏、答题卡、pptx |
| **题库检索** | 标签体系：知识点 / 题型 / 难度 / 来源年份 / 易错点；向量 + 标签混合检索 |
| **OCR** | 拍照识题、识别学生作业本 |
| **课堂小工具** | 计时器、随机点名、小组计分——低技术含量但高日活 |

**红线**：数学正确性是生死线。一次错答案，教师就不会有第二次打开。
建议双检验：CAS 求解 + 第二次独立路径求解，两者一致才输出。

## 4. 高价值场景（比「写教案」更痛）

全自动写教案其实是伪需求：教师不信任，且各校有固定模板。真正会被反复用的是：

- **变式生成器**——给一道题，产出同源题 / 改数 / 改问法 / 逆向命题 / 一题多解，每个都过 CAS 校验
- **错题诊断**——从学生作业反推错误类型（概念性 / 计算性 / 审题 / 书写规范），生成针对性 3 题
- **分层作业**——同一知识点 A/B/C 三档，10 秒出
- **四件套一致性**——教案 ↔ 课件 ↔ 学案 ↔ 作业，单一 source of truth 多种导出，改一处全联动
- **双向细目表命题**——先定「考点 × 能力层级」分布表，再按表选题组卷，避免「看着像卷子但结构乱」
- **中考溯源**——这个知识点近 5 年本地中考怎么考、分值多少、易错在哪
- **提问链设计**——苏格拉底式追问脚本 + 预设学生错误回答及应对
- **课后复盘**——教师一句话语音 → 结构化教学反思，沉淀回该课时节点，下一届直接复用

最后一条最易被忽略，却是让产品**越用越值钱**的飞轮。

## 5. 交互形态

- **不要做成纯聊天**。三栏：左=教材树，中=产物 tab（可编辑、可版本回退），右=Agent 对话。
- **产物必须可编辑**。教师一定会改；改动本身就是最好的偏好信号。
- **人在环**：生成 → 教师标注「这题太难 / 这个引入不好」→ 写回教师档案 → 下次生成自动规避。
- **离线与内网**：学校网络普遍差。考虑本地小模型兜底 + 本地题库缓存，至少保证检索和排版能离线跑。

## 6. 技术骨架

- **客户端**：Tauri（体积小、Windows 友好，学校机器普遍老旧）或 Electron。
- **Agent loop**：Claude Agent SDK。
- **工具拆分为多个 MCP server**：题库 / 绘图 / 排版 / 学情。这样各校可替换自己的题库实现，也便于单独迭代和测试。
- **文件即数据库**：一个课时 = 一个文件夹。

```
lessons/
└── 人教八下/17-勾股定理/02-勾股定理的逆定理/
    ├── meta.json        # 课标映射、难度、课时数、状态
    ├── lesson.md        # 教案（source of truth）
    ├── problems.json    # 关联题目
    ├── reflections.md   # 逐届教学反思
    └── assets/          # 图、导出的 docx/pptx
```

好处：git 版本化、教师能直接打开看、能拷给同事、能进教研组共享盘，不需要理解「系统」。

- **评测**：建自己的 eval 集（≥100 道人工标注题），持续测生成题的**答案正确率**与**难度标注准确率**。这是唯一能证明「比通用大模型强」的东西。

## 7. 主要风险与坑

| 风险 | 应对 |
|---|---|
| 数学出错 | CAS 双检验；宁可拒答不可错答 |
| Word 公式变图片 | 走 OMML；导出后自动打开校验一次 |
| 教材版本/地区差异大 | 教材树做成可配置数据，不硬编码 |
| 教师不信任全自动 | 定位为「半成品加速器」而非「一键生成」，永远保留人工修改入口 |
| 学情数据隐私 | 学生数据默认本地存储，不出校 |
| 做太宽没人用 | 见下节 MVP |

---

## 8. MVP 建议

不要横向铺开。挑一个窄口子打穿：

> **「一元二次方程」单元**：变式生成（含 CAS 校验 + 参数控制） + 分层作业 + Word 导出（公式可编辑）。

交给一位真实教师用两周，唯一验收指标：**他是否会主动第二次打开**。

跑通后按顺序扩：错题诊断 → 四件套联动 → 组卷 → 教学反思沉淀。
