# 结论：第一版做什么客户端

> 对 [chatgpt.md](chatgpt.md) / [claude.md](claude.md) / [grok.md](grok.md) / [zcode.md](zcode.md) 四份构想笔记的收敛。
> 整理日期：2026-08-19

---

## 一、四份文档已经达成的共识（不再讨论）

- **不做聊天框，做工作台**。判断标准两份文档独立写出了同一句话：
  *"如果老师复制提示词去任何聊天框都能得到同样结果，这个功能就没做成 harness。"*
- **产物必须落盘成文件，且可编辑**。教案 / 学案 / 卷子是老师要带走的东西，聊天记录不是。
- **三栏形态**：左 = 教材树 / 文件树，中 = 产物 tab（可编辑、可版本回退），右 = Agent 对话。四份都指向"教师版 Cursor / ZCode"。
- **CAS 验算是生死线**。这是唯一能证明"比通用大模型强"的东西，四份文档全部单列。
- **只做教师端**。不做学生端、家长端、积分商城。
- **窄口切入**：单一教材版本 × 单一年级 × 单一章节。

## 二、唯一的实质分歧：第一刀切在哪

| 文档 | 主张的 MVP 入口 |
|---|---|
| zcode.md | "备一节课"全流程：教案 docx + 课件 pptx + 分层作业 |
| chatgpt.md | 上传教材 → 生成备课资料 + 作业分析 |
| claude.md | 变式生成 + 分层作业 + Word 导出，**明确反对**先做教案 |
| grok.md | 三个 Skill 同时上（备课 / 出题 / 错因），但只强制 `verify_algebra` |

## 三、决定

**做一个 Windows 桌面客户端，三栏骨架一次搭好，但第一版只上「出题 / 变式 / 分层作业」这一个 Skill。**

采纳 claude.md §4 的判断——全自动写教案是伪需求，其余三份没有正面反驳它。教师不信任、各校有固定模板、改到面目全非，连"他是否采纳了"都测不出来。

选出题这一刀的理由：

1. **唯一能被机器验证的产物**。CAS 过一遍就知道对不对，差异化立刻可证明。
2. **频次最高**。作业天天要留，能撑起日活。
3. **采纳率可测**。导出了几道、改了几道，是最干净的产品信号。
4. **产物小、导出简单**。不用啃 pptx 那块硬骨头。
5. **是备课的真子集**。跑通后向上长成全流程，不是推倒重来。

### 第一版范围

- 人教版九年级上册 **第 21 章 一元二次方程**
  （原先写的「八下一元二次方程」是错的：八下第 17 章是勾股定理，
  一元二次方程在九上第 21 章。二次方程也正好是 CAS 验算最好使的地方。）
- 本地文件工作区：一个课时 = 一个文件夹（Markdown + JSON + assets）
- 一个 Skill：**分层出题 / 变式生成**
- `verify_algebra`（SymPy）**必须上线**
- 每道题是带状态的对象，用 grok.md §6 的三态：
  - **绿** = CAS / 标签 / 解析三关都过 → 可导出给学生
  - **黄** = 开放题、几何缺图、检查器覆盖不到 → 仅教师预览
  - **红** = 验算失败或与解析矛盾 → **禁止导出**
  - 这个状态要做得像 git 的 unstaged 一样显眼
- 导出 Word，公式走 **OMML**（可编辑，不是图片）——教研组一定要改，这条不能省

### 完成情况（2026-08-20）

| MVP 承诺 | 状态 |
|---|---|
| 本地文件工作区（一个课时 = 一个文件夹） | ✅ |
| 分层出题 | ✅ |
| 变式生成 | ✅ 每道题卡片上的「出变式」按钮 |
| `verify_algebra` 双路径 | ✅ 由 `save_problems` 强制执行，模型伪造不了 |
| 绿 / 黄 / 红三态 | ✅ 色带 + 徽标 + 汇总，红色虚线边框并压暗 |
| 导出 Word（OMML 可编辑公式） | ✅ 工具栏「导出 Word」，含答案可切换 |

超出原范围但做了的：教材树（两版全六册 255 知识点 + 51 条错因）、
几何配图并校验图与题干同源、点知识点建课时、文件监听实时刷新。

### 第一版明确不做

- 教案全文生成、PPT 生成
- OCR 拍照识题、错因诊断（grok.md 想放进 MVP，往后放——它依赖题库和解法树）
- "上传教材自动建库"（chatgpt.md 的入口设想）——全书 OCR + 结构化是大工程，第一版教材树用预置配置数据
- 多版本教材对齐、学情长期档案、教研组协作

### 验收标准

交给一位真实教师用两周，唯一指标：**他是否会主动第二次打开**。

### 后续扩展顺序

出题 → 错因诊断 → 备课四件套联动 → 组卷（双向细目表）→ 教学反思沉淀

## 四、暂定的两个前提（可推翻）

来自 claude.md §9 的待定问题，第一版按以下假设走：

1. **题库**：第一版无题库，纯生成 + CAS 验证。检索层留接口不实现。
2. **用户单位**：单个教师。协作与权限不进第一版。
