# 初中数学教师 Harness 客户端：构想笔记

> 备课资料是工作区，客户端是教师版 Cursor。Agent 改文件、出 diff、等教师采纳——不是再做一个会聊天的教案生成器。
> 整理日期：2026-08-19

## 一、核心定位

教师真正要带走的是文件：教案、学案、分层卷、板书、错因单。Harness 的工作是改这些文件、给出 diff、等老师点采纳。模型可以多聊两句解释，但主产物必须落盘。

通用 ChatGPT 套壳试三次就会翻车：课标记错、题算错、教案不像自己的课。判断标准可以更硬一点：**如果老师复制提示词去任何一个聊天框都能得到同样结果，这个功能就还没做成 harness。**

三句话收口：

- **工作区**：教案 / 学案 / 题库 / 错题 当成「代码库」
- **循环**：检索 → 起草 → 验算 → diff → 采纳
- **人在环内**：教师永远是最后一公里

## 二、为什么是 Harness，不是 Bot

日常备课是短循环，不是一次生成：

1. 检索课标、教材小节、真题、本班弱项
2. 起草到工作区
3. **验算**（代数过 CAS，几何查条件是否够用）
4. 老师改一刀：再出 3 道变式、换成自己惯用的引入
5. 导出 Word / PDF / 一体机页

差异化几乎全在第 3 步。数学产品死于「看起来像教案，算出来是错的」。生成器可以很便宜；检查器必须很苛刻。建议把「未验证」做成一等状态，和 git 的 unstaged 一样显眼。

## 三、四层结构

从外到内：教师看见的是工种按钮和文件树；模型看见的是会话包、技能说明书和工具。

| 层 | 职责 | 老师侧看得见什么 |
|---|---|---|
| 教师客户端 | 文件树 + 预览；拍照、圈知识点、拖分层；采纳 / 驳回 diff；一体机投屏、导出家长群 | UI |
| 会话包 | 年级班级、教材版本、本课知识点、课时、学情切片、教师风格 | 没有会话包，生成必空泛 |
| Agent 循环 | 路由到对应 Skill；调工具，不凭记忆编课标；写工作区文件，不出长聊；失败就标黄，不编造绿勾 | 一轮任务的过程 |
| 接地层 | 课标知识图谱、教材 + 真题库、CAS / 几何检查器 | 这层决定能不能上课堂 |

## 四、用三个工种驱动，而不是一个万能聊天框

不要做一个万能助手。先做三个 Skill，入口写成老师会说的话。课堂实时语音、全自动批改、家长端，都可以后做。办公室里 10 分钟能用完一轮，比功能清单重要。

### 1. 课时备课

- **教师怎么开口**：下周要上「一次函数的图象」，45 分钟，人教版八上
- **会话包必须带上**：课标条目 + 教材小节 + 本班上周作业弱项 + 教师惯用引入风格
- **循环**：检索对标课例 → 起草教学目标/活动/板书 → 对齐核心素养与课时容量 → 出 3 道课堂变式并验算
- **落到工作区**：`教案.md` · `板书.tex` · `学案.md` · `课堂题.json`（带验证戳）
- **什么时候才算可信**：知识点不超纲；例题可算；活动时长合计 ≤ 40 分钟

### 2. 分层出题

- **教师怎么开口**：针对「分式方程」出 8 道作业：基础 4 / 提升 3 / 拓展 1
- **会话包必须带上**：知识点图 + 近三年本市中考同源题 + 本班错误分布 + 已布置过的题（去重）
- **循环**：选题或生成 → 符号验算 + 多解检查 → 难度与知识点打标 → 教师点选变式方向再迭代
- **落到工作区**：`作业卷.md` · `答案解析.md` · `双向细目表.csv`
- **什么时候才算可信**：每题必须绿——可算、无歧义、标签与解析一致。优先检索校本/真题，再生成。

### 3. 错因诊断

- **教师怎么开口**：拍照或导入 40 份作业中的 3 道解答题
- **会话包必须带上**：标准解法树 + 常见错因库（计算 / 概念 / 审题 / 书写）+ 该生近期轨迹
- **循环**：识别步骤 → 对齐解法树 → 归类错因 → 生成订正题（同源变式）并验算
- **落到工作区**：`班级错因报告.md` · `个别订正单.md` · 下节课补救 5 分钟设计
- **什么时候才算可信**：错因可追溯到具体步骤；订正题与原错点同构，数字已换

## 五、工具清单：少而硬，不要做成插件市场

课标不要让模型背，让它查。

| 教师动作 | 工具名 | 接地什么 | 硬约束 |
|---|---|---|---|
| 检索课标/教材 | `search_curriculum` | 2022 课标、人教/北师大小节、核心素养条目 | 生成前必调，禁止凭记忆写目标 |
| 检索题库 | `search_items` | 真题、校本卷、已布置去重、难度与知识点 | 出题优先检索再生成，减少胡编 |
| 符号验算 | `verify_algebra` | SymPy / CAS：方程、因式分解、函数值 | 代数题未绿禁止写入学生卷 |
| 几何约束 | `verify_geometry` | 尺规条件、全等/相似判定、长度角度一致性 | 缺图或条件不足时标黄，不装成可做 |
| 作图 | `render_figure` | 函数图象、几何草图、数轴、统计图 | 图与题干条件必须同源生成 |
| 学情记忆 | `class_memory` | 班级弱项、个人错因、教师口吻与板书习惯 | 每次会话注入，否则永远是网课教案 |
| 导出 | `export_pack` | Word / PPT / PDF / 图片（家长群、一体机） | 教师交付物，不是聊天记录 |

## 六、验算闭环（差异化在这里）

每道题做成带状态的对象。没有验证戳的文字，只是散文，不是题。

| 状态 | 含义 | 能否发给学生 |
|---|---|---|
| 绿 | CAS / 几何 / 标签三关都过 | 可以 |
| 黄 | 几何缺图、开放题、或检查器覆盖不到 | 仅教师预览 |
| 红 | 验算失败、超纲、或与解析矛盾 | 禁止导出 |

一题最低字段：

- 题干（含图引用）
- 答案 + 分步解析
- 课标知识点 ID、难度、题型
- 验证器结果（绿/黄/红 + 日志）
- 变式种子（同结构可换数）

缺任何一项，就不是题库对象。

## 七、会话包与客户端手势

每次调用至少带齐：年级班级、教材版本、本课知识点、课时、本班近期弱项、老师口吻。没有学情，生成永远是网课模板。

客户端手势要对着老师，不要做成程序员 IDE 的 slash command 墙：

- 拍照作业
- 圈知识点
- 拖分层
- 一键变式
- 驳回后只改「引入太闹」这一段

## 八、MVP 刀法

**一个人教版 × 一个年级（建议八上函数或方程）× 上面三个工种 × 代数验算必须上线。** 先让一位老师下周真的拿去上课。

做：

- 人教版八年级上，函数或方程一章
- 本地工作区（Markdown + JSON + 图）
- 三个 Skill：备课 / 出题 / 错因
- `verify_algebra` 必须上线
- 导出 Word 或 PDF 即可

先不做：

- 全学段、全版本教材对齐
- 自动批改全部解答题 OCR
- 课堂实时语音助教
- 家长端 App、积分商城
- 无检查器的「智能 PPT 一键生成」

全版本对齐、几何自动作图打满、OCR 全卷批改，都是验证了「老师愿意每周回来」之后的事。

## 九、最容易走歪的三条路

1. **做成通用 ChatGPT 套壳**：教师试用三次就会发现课标错、题算错、不像自己的课。
2. **做成内容农场**：只堆教案模板，没有学情和工作区。
3. **做成 IDE 玩具**：交互像程序员，备课老师在办公室 10 分钟里用不起来。

## 十、建议的下一步

二选一，杠杆都够：

1. 把「会话包 + 工具契约」写成正式 spec
2. 直接搭最小工作区：Markdown 教案 + JSON 题库 + 一个验算循环
