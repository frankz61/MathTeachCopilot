# MathTeachCopilot 构想笔记

> 初中数学教师备课与日常使用的 harness 客户端
> 整理日期：2026-08-19

## 一、核心定位：做"老师版的 ZCode"，而不是"数学老师的聊天套壳"

ZCode 本身就是 harness 的最佳范本：它不是把模型包一层对话框，而是**上下文工程 + 工具 + 技能 + 资产沉淀**的组合体。程序员用它写代码很顺，是因为工具（读写文件、跑命令）、技能（pptx、docx）、项目记忆（AGENTS.md）都在替模型"垫场"。

我们的产品要做同样的事：老师说出"备人教版八下 19.1.1 变量与函数"，剩下的一切由 harness 替她垫场。对照着拆：

| ZCode 里的机制 | 教师版 harness 的对应物 |
|---|---|
| 读代码库、AGENTS.md | 自动注入课标（2022 版）对应条目 + 教材本章内容 |
| 文件读写工具 | 产出真正的 .docx 教案、.pptx 课件、.xlsx 成绩单 |
| skills（如 pptx、pdf） | "备课技能""组卷技能""试卷分析技能"——打包好的工作流 |
| 项目记忆 | 班级学情档案、她的教学习惯、往届教案库 |
| 权限确认 | 重要产出（如整套试卷）先预览再定稿 |

**判断标准：如果老师复制提示词去任何一个聊天框都能得到同样结果，那这个功能就没做到 harness。**

## 二、场景地图：围绕教师的五个环节

1. **备课**（最强刚需）：输入章节 → 一课备齐：教案、PPT 课件、导入情境、例题+梯度变式、板书设计、分层作业（A 基础 / B 提升 / C 挑战）。
2. **上课**：函数图像、几何动态演示的生成（GeoGebra 脚本或动画参数），课堂即时出题。
3. **作业与组卷**：按"知识点 × 题型 × 难度 × 分值"双向细目表组卷，自动排版成可打印试卷。
4. **测评分析**：上传成绩 Excel → 按知识点算得分率 → 定位薄弱点 → 生成补救练习。这是老师手工做最痛苦、工具价值最直观的一环。
5. **沉淀**：错题本、命题素材库、跨学期可复用的教案资产——这是用户离不开产品的护城河。

## 三、数学的"硬骨头"——也是差异化所在

通用大模型做数学教育产品，栽就栽在这几处，谁解决谁赢：

- **公式与图形的"最后一公里"**：模型输出的 LaTeX 怎么变成 Word 里的公式、PPT 里的公式？几何题怎么配出精确的图（不能三角形画成钝角还说是直角）？需要专门的渲染/作图工具层（OMML 转换、matplotlib/GeoGebra 出图），是纯聊天给不了的。
- **题目正确性自检**：LLM 出题最大的坑是"题目无解 / 数据自相矛盾 / 答案算错"。harness 里应挂一个**验证器工具**——把生成的题丢给符号计算（如 SymPy）核答案、核条件，过了再给老师。这一条做到，信任感立刻不同。
- **超纲检查**：出题时自动对照课标，标红"分式方程是'可解'要求但'无理系数'超纲"。中考命题研究里这是真功夫，也是真卖点。

## 四、第一个最小闭环

别做大而全。第一版只做一件事并做穿：**"备一节课"全流程**——

选章节 → 教案（docx）→ 课件（pptx，含公式和图）→ 分层作业（可打印），中间所有课标注入、图形生成、答案校验由 harness 静默完成。

这个闭环跑通，后面组卷、分析都是同一套底座上的新技能而已。

## 五、底座设计要点

技术选型不必急，但架构设计时就给四样东西留位置：

1. **模型路由**：打标、批量生成用便宜模型，命题用强模型。
2. **知识库**：课标 + 教材 + 题库，结构化优于纯 RAG。
3. **工具层**：文档生成（docx/pptx/xlsx）、作图（matplotlib/GeoGebra）、符号验证（SymPy）。
4. **资产库**：用户产出的每样东西都存下来，变成下一次的上下文。

## 六、下一步

把最小闭环拆成具体的项目骨架：目录结构、技能定义、工具清单，直接在仓库里搭起来。
